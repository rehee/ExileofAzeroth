## DQQ 的挂机机制（调研结论）
DQQ.Web.Component 的 `IdleService.HeartBeatHandler` 按心跳推进挂机：
- **在线模式**：战斗由 DQQ 服务器在后台计算。客户端只是定时查询最新一条录像（`ITableQueryService`），有新录像就播放（`GetReplayRequestDTO` 重放）。
- **离线模式**：客户端自己算：角色 `AutoCombat` 为真且选了地图时，用 `RequestCombatRandom` 跑一场，生成录像并结算奖励。
- 是否挂机、挂哪张图由角色的 `AutoCombat`、`SelectedMap` 决定（`ICharacterService.SelectMap` 等）。
- `IdleService` 依赖一个页面层的状态对象（`fullParameter`：`GetStatus`、`GetSelectedCharacterDTO`、`RaiseEvent` 等），runtime 要提供这些。

结论：runtime 不另写挂机逻辑，而是定时调用 DQQ 的 `HeartBeatHandler`，并把它的事件（进度、新录像）转给客户端。

## 设计
1. **藏身处布局**是一份配置（runtime 下发，`scene.hideout`）：位置、每个设施的模型（游戏物件 display id）、坐标、朝向、触发半径、对应界面。
2. **设施交互**：桥接创建游戏物件（`ObjectCreate` GameObject）或 NPC；玩家点击时客户端发 `GameObjUse` / `GossipHello`，桥接接住后发插件消息 `open;<界面>`，插件打开对应窗口。走近自动打开可选。
3. **地图仪**：打开地图选择界面（PLAN-0005），选图后可"开始挂机"或"进入观看当前战斗"。
4. **挂机**：runtime 每秒调用一次 `HeartBeatHandler`；挂机状态（地图、第几波、进度、本场时长、最近结果、收益）经 `idle.*` 推给插件，屏幕上方常驻一个进度条。
5. **观看**：在线模式下"观看"就是回放最新录像（现有流程）；离线模式可以直接观看正在计算的那一场（runtime 改为观看节奏）。

## 任务清单
### A. 场景
- [ ] 选定藏身处位置（北郡、暴风城某处，或其他安静平整的地点），确定设施布局草图，与用户确认
- [ ] 桥接：按配置创建游戏物件/NPC（`ObjectCreate` GameObject 的字段、模型、名字查询应答 `GameObjectQuery`）
- [ ] 桥接：接住 `GameObjUse`、`GossipHello`，转成插件消息 `open;<界面>`
- [ ] 插件：按 `open;…` 打开对应窗口
- [ ] 进入战场时隐藏这些物件，回来时恢复（D28）

### B. 挂机
- [ ] runtime：为 `IdleService` 提供页面状态对象，定时调用 `HeartBeatHandler`；在线模式验证"服务器挂机 + 本地播放最新录像"的链路
- [ ] 协议：`idle.status`（地图、状态、进度、波次、最近结果、收益）、`idle.start` / `idle.stop`（调用 `SelectMap`、切换 `AutoCombat`）
- [ ] 插件：常驻进度条与挂机面板（开始、停止、当前地图、最近几场结果）
- [ ] 观看：从挂机面板进入观看（在线：回放最新录像；离线：观看正在计算的战斗）

### C. 检查
- [ ] 挂机一小时：runtime 内存稳定、无卡顿；与 DQQ 网页版对比收益一致
- [ ] 退出游戏时挂机停止（D26）

## 验收标准
- 进入游戏后站在藏身处，点地图仪选图开始挂机，进度条持续更新，收益与 DQQ 网页版一致。
- 点各设施能打开对应界面。
- 随时可以进入战场观看，结束后回到藏身处。
